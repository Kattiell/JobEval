7. TYPST STRING DISCIPLINE  (syntax will break without this)
══════════════════════════════════════════════════════════════
Typst MARKUP treats these as syntax, not text:
  @   citation / label          → emails like name@firma.de
  $   math mode                 → $60,000 or $ amounts
  _   emphasis                  → linkedin.com/in/first_last
  *   strong/emph               → 5* YoY, footnotes
  #   code start                → C#, F#, issue #12
  < > raw/tags                  → HTML leftovers in pasted CVs
  `   raw                       → inline code fragments
  [ ] content blocks            → array-like notes
  https URLs with _ or @        → same problem if typed in markup

Rule: every candidate-supplied fragment lives inside a "double-quoted string" (#let x = "...") or a #"..." string, then interpolated as #x.
Inside "strings", @ $ _ * # are ordinary characters. The only escapes in strings are \\ and \".

Do this:
  #let email = "pedro@firma.de"
  #let url = "https://www.linkedin.com/in/pedro_giacomo"
  #let money = "60 000 EUR"
  #let skill = "C#"
  #link(url)[LinkedIn]
  #email   // interpolation of a string is safe

Never do this in markup/content:
  pedro@firma.de
  https://linkedin.com/in/pedro_giacomo
  $60,000
  C#
  5*_years_

Prefer EUR with thin spaces (60 000 EUR) over $ amounts. If a dollar figure must appear, it still goes in a string: "USD 60 000".
Use #link(url)[visible label] for every URL; the URL argument is a string.
If a pasted CV contains backslashes or quotes, escape them inside the string: \\ and \".

Before sending Typst, scan the fenced block for raw @ $ _ # in markup (outside "strings" and outside comments). If found, move that text into a #let string.
